# Agent Routing Matrix

> All selection decisions are made by `backend/src/services/agent-selector.ts` via `buildAgentAssignments()`.
> There is no hardcoded phase-to-agent mapping — selection is purely score-based at runtime.

## Selection Rule Summary

```
totalScore = capabilityOverlap(+2/word) + domainHeuristic(+4..+8) + engineerBroadBonus(+4..+7)
Winner = highest totalScore; ties broken by agent[] array order (filesystem load order)
Fallback = agents[0] if all scores are 0
```

Evidence: `backend/src/services/agent-selector.ts` lines 33–162

## Phase-to-Agent Assignment (Typical `build_new_app` Run)

> Task descriptions are generated by `RoadmapGenerator` using the compact directive format.
> Actual agent assignment depends on those descriptions at runtime.

| Phase | Typical Task Description Pattern | Expected Agent | Confidence |
|---|---|---|---|
| Foundation / Setup | `CREATE: tsconfig.json \| strict:true \| ...` | Engineer | HIGH — "create" triggers broad bonus |
| Foundation / Setup | `CREATE: src/types/index.ts \| interfaces...` | Architect Agent or Engineer | MEDIUM — "interfaces" slightly favors Architect |
| Core Features | `IMPLEMENT: src/services/foo.ts \| ...` | Engineer | HIGH |
| Core Features | `CREATE: src/routes/bar.ts \| Express router...` | Engineer | HIGH |
| Testing | `WRITE: tests for src/services/foo.ts \| describe/it/expect` | Test and Validation | HIGH — "describe/expect" = +8 |
| Hardening | `REVIEW: src/services/*.ts \| defects \| correctness` | Critic | HIGH — "review/defect" = +6 |
| Repair (generated) | `FIX: src/services/foo.ts \| TS2322 error at line 42...` | Engineer | HIGH — "fix" triggers broad bonus |

## Input / Output Contract Per Agent (VERIFIED from YAML files)

| Agent | Input Schema Keys | Output Schema Keys | Prompt Format Enforced |
|---|---|---|---|
| Engineer | specification, requirements[], context | implementation, tests[], documentation | `## File:` blocks |
| Researcher | goal, context | facts[], risks[] | FACTS: / RISKS: sections |
| Critic | implementation, specification, requirements[] | issues[{severity,file,line,issue,fix}], ratings, improvements[] | `## File:` blocks for corrections |
| Synthesizer | researcher_output, engineer_output, critic_output, goal | roadmap[], deliverables[], summary, conflicts_resolved[] | Phases with objective/deliverables |
| Commissioner | synthesized_plan, goal, estimated_cost, estimated_time | value_score(0-10), recommendation(go/no-go/conditional), rationale, conditions[], improvements[] | JSON only |
| Supervisor | run_id, agent_outputs, goal | quality_score(0-10), feedback[], insights[], agent_scores{} | JSON only |
| Architect Agent | Repo Analyst brief, requirements, constraints | design blueprint, interface contracts, rollout plan, implementation slices | Structured sections |
| Test and Validation | acceptance criteria, architecture handoffs, risk matrix | traceability matrix, test results, coverage gaps | `## File: *.test.ts` blocks |

## Hardcoded vs Dynamic Routing

| Routing Aspect | Hardcoded? | Source |
|---|---|---|
| Phase execution order | YES — sequential, no parallelism | runs.ts:278 loop |
| Task execution order within phase | PARTIALLY — producers before reviewers enforced | gate.ts:26 |
| Agent assigned to task | NO — score-based dynamic | agent-selector.ts |
| Model selection | YES (Anthropic API only) | task-executor.ts:299 — single LLMClient |
| Max task tokens | YES — `maxTokens: 4096` | task-executor.ts:322 |
| Max repair generations | YES — `maxRepairGenerations: 3` | repair-policy.ts:30 |
| Repair agent selection | NO — same score-based dynamic as normal tasks | runs.ts:475 |
| Escalation target | YES — always `'Supervisor'` | repair-policy.ts:30 |
| Job type default agents | YES — `job_types.json` lists them but they are not enforced | contract-compiler.ts:73 |
