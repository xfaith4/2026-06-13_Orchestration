## Failure Scenarios & Recovery

This test case can fail at various points. The orchestration system should handle each gracefully:

### Failure 1: LLM Timeout
- **Where:** Task execution (any phase)
- **Symptom:** Agent call takes > 60 seconds
- **Recovery:** Retry with lower maxTokens or simpler prompt
- **Evidence:** RunEventLog shows `agent_blocked` → `agent_started` (retry)

### Failure 2: Generated Code Has Syntax Errors
- **Where:** Task 4-2 (TypeScript validation)
- **Symptom:** `tsc --noEmit` returns exit code 2
- **Recovery:** ProjectValidator reports errors, agent re-generates with feedback
- **Evidence:** Task 4-2 status: `pending` → `in-progress` → `failed` → `in-progress` (repair) → `completed`

### Failure 3: File Already Exists (Merge Conflict)
- **Where:** ProjectWriter.write() on second run of same runId
- **Symptom:** File at path already exists
- **Recovery:** Overwrite (current behavior) or prompt user (future)
- **Evidence:** AuditLog shows `OVERWRITE` action

### Failure 4: Dependency Mismatch
- **Where:** Task 3-2 (routes) references exports from Task 2-2 (services) that don't exist
- **Symptom:** TypeScript compilation error: "Cannot find name 'addItem'"
- **Recovery:** Agent re-generates Task 2-2 with correct exports, then re-generates Task 3-2
- **Evidence:** RunEventLog shows multiple attempts, repair loop active

### Failure 5: Out of Budget
- **Where:** Total cost exceeds limit before run completes
- **Symptom:** Cost tracker crosses threshold after task N
- **Recovery:** Stop execution, report to user, suggest cheaper model or shorter roadmap
- **Evidence:** Run status: `running` → `failed` with reason `budget_exceeded`

   - Enforce A2A contracts between agents
   - Verify agents cannot produce out-of-contract output

   - Lessons learned from past runs applied to new ones
   - Verify cost/time reduction on second similar project

Each iteration builds on the success of this minimal test case.
