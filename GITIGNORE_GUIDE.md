# .gitignore Guide

This document explains what is ignored in git and why.

## Quick Reference

| Category | Ignored | Reason |
|----------|---------|--------|
| **Dependencies** | `node_modules/`, lock files | Regenerated via `npm install` or `yarn install` |
| **Build artifacts** | `dist/`, `build/`, `.next/` | Regenerated during build |
| **IDE settings** | `.vscode/`, `.idea/`, editor configs | Machine-specific, not part of codebase |
| **Environment variables** | `.env`, `.env.local`, `.secrets/` | Contains sensitive data, never commit |
| **Runtime state** | `.orchestration/state.json`, logs | Auto-generated, changes per execution |
| **OS files** | `.DS_Store`, `Thumbs.db` | Machine-generated junk |

## What IS Committed

- `CLAUDE.md` — Project contract (committed)
- `.orchestration/STATE_SCHEMA.md` — State contract definition (committed)
- `orchestrator/Invoke-RoadmapOrchestrator.ps1` — Source code (committed)

### Documentation
- `ORCHESTRATOR_SETUP.md` — Setup guide (committed)
- `ORCHESTRATOR_FIXES_SUMMARY.md` — Change summary (committed)
- All `.md` files explaining the system (committed)

### Directory Structure
- `.orchestration/` directory (with `.gitkeep` to preserve structure)
- `orchestrator/` directory
- `agents/`, `contracts/`, `lib/`, `Prompts/` (existing, committed)

## What IS NOT Committed

### Runtime Artifacts
```
.orchestration/state.json          ← Changes per orchestration run
.orchestration/orchestrator.log    ← Execution logs
.orchestration/capsules/*.txt      ← Phase memory capsules
.orchestration/capsules/*.json     ← Parsed outputs
```

**Why?** These are **generated per run** and will differ across executions. Committing them creates merge conflicts and noise.

### Node/npm
```
node_modules/                      ← Installed dependencies
package-lock.json                  ← Dependency lock file
yarn.lock                          ← Yarn lock file
```

**Why?** Regenerated by `npm install` or `yarn install`. Lock files optional (depends on team preference; this .gitignore omits them to avoid merge conflicts, but you can adjust).

### Environment Secrets
```
.env
.env.local
.secrets/
credentials.json
```

**Why?** **Never commit secrets.** These files contain API keys, credentials, or local configuration that should not be in version control.

### Build Outputs
```
dist/
build/
.next/
out/
```

**Why?** Generated during build process, regenerated on each machine.

### IDE/Editor Files
```
.vscode/
.idea/
*.swp
.DS_Store
```

**Why?** Machine-specific settings; different developers use different IDEs and configurations.

## When You Need to Commit Configuration

**If you need shared IDE settings** (e.g., team linting rules):
- Use `vscode/extensions.json` or `.editorconfig` (not `.vscode/settings.json`)
- Document in a README section or CLAUDE.md

**If you need shared environment defaults:**
- Create `.env.example` with placeholder values (no real secrets)
- Document required variables in README

**Example .env.example:**
```bash
CLAUDE_API_KEY=your-key-here
MAX_TOKENS=4096
DEBUG=false
```

## For First Commit

Before your first git commit:

1. ✅ `.gitignore` is in place (this file)
2. ✅ `.orchestration/.gitkeep` preserves directory structure
3. ✅ `.orchestration/capsules/.gitkeep` preserves capsules directory
4. ✅ No `.env` file is present (use `.env.example` if needed)
5. ✅ No `node_modules/` directory (or it's properly ignored)
6. ✅ No runtime state files in the repo

## Troubleshooting

### "I committed .env by accident"

Once committed, git remembers it even if you add .gitignore. Fix it:

```bash
git rm --cached .env
git commit --amend -m "Remove .env from history"
```

For entire directories:
```bash
git rm --cached -r .orchestration/state.json
git commit --amend -m "Remove runtime state from history"
```

### "I need to commit a .env variant"

Create `.env.example` with placeholders instead:
```bash
# .env.example (safe to commit)
DATABASE_URL=your-database-url-here
API_KEY=your-api-key-here
```

Then add to `.gitignore`:
```
.env
.env.local
```

### "state.json is showing as changed but I don't want to commit it"

That's correct behavior. It's ignored and shouldn't appear in git status. If it does, check that `.gitignore` is properly saved:

```bash
git status --ignored
```

This shows ignored files. If `.orchestration/state.json` appears there, you're good.

## Notes on This Project

This .gitignore reflects:
- **Frontend + Backend TypeScript/Node stack** (React + Express)
- **PowerShell orchestration scripts** (not ignored)
- **Machine-generated runtime state** (.orchestration/ outputs, not ignored except state/logs)
- **Security-first approach** (.env, credentials, secrets ignored)
